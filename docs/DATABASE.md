# База и резервная копия

SQLite mgym.db, user_version=3. WAL, foreign_keys=ON.
workouts(id, started_at, finished_at, exercises); sets(id, workout_id, exercise, weight, reps, kind, technique, rir, rpe, comment, position); settings(key,value).
Даты — epoch milliseconds, календарь использует дату начала в часовом поясе устройства.

Миграция 1→2 добавляет position, заполняя его прежним id. Данные, комментарии и старые типы подходов не изменяются. Миграция проверяется тестом на базе версии 1.
Миграция 2→3 перестраивает таблицу sets, расширяя ограничение exercise для DEADLIFT и SQUAT. ID, вес, повторы, комментарии и порядок старых подходов копируются без изменений. Проверены переходы с версий 1 и 2.
Список сортируется по workout_id, exercise, position, id. Перестановка выполняется транзакцией, только для полного набора уникальных ID одного упражнения одной тренировки. Новый подход добавляется в конец. Редактирование сохраняет позицию.

Одна активная тренировка защищена частичным уникальным индексом, связи — внешним ключом. Изменение веса и удаление подходов доступны в активной тренировке; изменение порядка доступно также после завершения.
Завершение запрещено без подходов. Черновик сохраняется отдельно в settings.draft.

JSON format=MGym, version=1 остаётся совместимым: порядок задаёт массив sets. Импорт восстанавливает position из порядка массива. Ограничение 10 МБ, 20 тысяч тренировок, 100 тысяч подходов.
Проверяются enum, числа, даты, IDs, связи, упражнения и одна активная тренировка. Замена проходит в транзакции после подтверждения. CSV следует сохранённому порядку, экранирует кавычки и защищает текст от формул.

Автоматическое Android backup отключено. Перенос — через экспорт пользователя.

Новые базы по-прежнему пусты. sounds хранится в settings; JSON дополняется необязательным sounds (по умолчанию true для старых файлов). Представление trainingDiary включает жим, тягу и приседания, исключая старые записи бицепса из рабочих экранов. prepareDiary закрывает старый активный сеанс только с бицепсом, сохраняя данные для совместимости backup, и сбрасывает старый черновик бицепса.

## Построчный ввод 0.2.1

Новая тренировка начинает черновик с пустыми weight/reps. appendRow сохраняет подход и очищает черновик в одной транзакции. finishWithRow сохраняет последнюю заполненную строку и завершает тренировку атомарно. Пустая строка не становится подходом; неполный ввод блокирует добавление новой строки и завершение до исправления или очистки. Схема базы не меняется.
