# Архитектура MGym

Домен не зависит от Android: Exercise, Workout, LiftSet, Draft. Вес хранится в кг как Double; ручной ввод принимает запятую.
UI на Compose читает состояние GymViewModel. ViewModel переживает поворот и пересоздание Activity.
Один Executor сериализует операции SQLite и файлов, Handler публикует результаты в UI.
Каждое изменение основного черновика ставится в очередь сохранения без debounce. Очередь добавления подхода идёт после записей его черновика.
Только успешная транзакция обновляет список подходов; ошибки показываются пользователю.

SQLiteOpenHelper владеет схемой; GymRepository — запросами и транзакциями. UI не вызывает SQLite.
BackupCodec отвечает за версионированный обмен; UpdateProvider позволяет заменить источник обновлений.

Навигация: пять сохранённых вкладок, отдельный экран активной тренировки, детали истории и результат. Back сворачивает тренировку, не завершает её.
При запуске активная тренировка восстанавливается из SQLite. Контроллер не создаёт новую тренировку при recomposition.

Компромисс этапа 0.1: snapshot всей базы после мутации. До поддержки десятков тысяч подходов нужны постраничные репозитории и SQL-агрегаты.
iOS не реализован: выбран существующий Android-проект, перенос домена возможен отдельно.
